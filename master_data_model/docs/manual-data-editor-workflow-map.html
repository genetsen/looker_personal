Decision Flow: What The Loader Solves

This is the useful flowchart for the tech team: it shows the decisions that prevent bad manual data from becoming reporting data.

Boundary

Is this only a request?

Yes: send email or Slack only. No validation, no warehouse write, no dashboard proof.

Detection

Did the Sheet value really change?

Compare visible values to source baselines and prior manual rows. Clear stale manual evidence when source catches up.

Validation

Is the edit valid?

Block bad dates, duplicate active edits, incomplete new rows, and partial-range planned metrics.

Grain

What kind of change is it?

Delivered metrics join by package/date. Metadata and flight dates apply package-wide.

Debugging

Dashboard still looks wrong?

Trace Sheet value, raw row, daily row, model, mart, and dashboard filters before changing logic.

Technical Notes

How the loader decides whether a Sheet value is an edit
  • Blank or source-matching metric cells are treated as no manual override.
  • Planned metrics compare against PRISMA package totals, not filtered mart sums.
  • Delivered metrics compare against source delivery baselines, not manual-affected final fields.
  • Prior raw manual rows help identify kept overrides, corrections, undos, and source catch-up.
What gets written to BigQuery
  • The raw table stores one row per editor row with current values, replacement values, validation status, and metadata overrides.
  • The daily table stores active valid metric edits at package/date grain for model joins.
  • Total fields ending in doNotSum repeat context across daily rows and should not be summed as daily measures.
How manual values merge into the model
  • Manual metrics join by package ID and date.
  • Manual metadata joins by package ID and can apply outside the edited metric date range.
  • Manual-only packages enter through a separate manual branch when identity, dates, metric, and metadata are valid.
Fastest debugging path
  • Trace the visible Sheet value, hidden baseline, hidden marker, raw manual row, daily manual row, model fields, mart fields, and dashboard filters.
  • A valid manual edit can change qa_row_data_source_primary to manual package edits.
  • A dashboard filtered to only DCM-classified rows can hide correct manual-backed delivery values.
